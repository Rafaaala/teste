1. Visão Geral do Sistema de Telas
O sistema possui três domínios de acesso via subdomínios distintos, cada um com seu conjunto de telas e perfil de usuário. Toda comunicação com o backend é feita via chamadas REST à API.

2. Domínio: cardapio.rest.com
Aplicação pública e responsiva acessada pelo cliente final via navegador ou PWA. Não exige conta para navegar. O cliente é identificado pelo telefone no checkout.

2.2. Tela — Checkout
Rota: /checkout  |  Pública
Tela de finalização do pedido. O cliente informa dados, endereço e método de pagamento. Fluxo crítico — qualquer fricção aqui é perda de venda.
Feature
Descrição
Endpoint(s)
Resumo do pedido
Lista de itens com quantidades e valores. Subtotal, taxa de entrega e total claramente visíveis. Botão para voltar ao cardápio.

Identificação por telefone
Campo de telefone é o primeiro do formulário. Após digitar, buscar cliente e preencher nome automaticamente se já existir.

Formulário de dados
Campos: nome completo, telefone, CPF (opcional). Se cliente já existe, campos pré-preenchidos e editáveis.

Botão de localização
Botão &apos;Usar minha localização&apos; aciona navigator.geolocation. Validar raio via API e exibir distância calculada.
POST /api/pedidos/validar-localizacao
Endereço salvo
Se cliente tem endereços, exibir lista para seleção rápida. Opção de cadastrar novo.
GET /api/clientes/telefone/:phone
Endereço manual
Formulário: CEP (auto-preenchimento via ViaCEP), rua, número, complemento, bairro, cidade, UF.
POST /api/enderecos
Seleção de pagamento
Dois botões de escolha visual: Pix (QR Code) e Cartão. Com ícones representativos.
—
Botão Finalizar
Cria o pedido e redireciona para a tela de pagamento correta.
POST /api/pedidos, POST /api/pagamentos
Estados e Comportamentos
Estado / Situação
Comportamento esperado na UI
Endereço fora do raio
Mensagem com distância real (ex: &apos;Seu endereço fica a 34km. Atendemos até 20km.&apos;). Botão Finalizar bloqueado.
Permissão de GPS negada
Ocultar botão de localização. Manter apenas o formulário manual.
Carrinho vazio
Redirecionar automaticamente para o cardápio.
CEP inválido
Erro inline no campo CEP. Não bloquear o formulário inteiro.
Cliente novo
Criar cliente antes do pedido: POST /api/clientes → POST /api/enderecos → POST /api/pedidos.

3.4. Tela — Histórico de Pedidos (Delivery)
Rota: /pedidos  |  Gerente, Admin

Feature
Descrição
Endpoint(s)
Tabela de pedidos
Colunas: #pedido, cliente, itens (contagem), valor total, método de pagamento, status (badge colorido), data/hora e ícone de NFC-e.

Botão de ação por linha: avança para o próximo status com confirmação em modal.
PATCH /api/pedidos/:id
Cancelar pedido

PATCH /api/pedidos/:id

Ícone de nota fiscal que abre o DANFE (PDF) em nova aba. Aparece somente quando invoice_status = autorizada.

Paginação
Componente de paginação padrão. Padrão de 20 itens por página.
GET /api/pedidos/historico?page=&amp;limit=
Fluxo de atualização de status
O gerente avança o status manualmente. Cada mudança dispara notificação WhatsApp ao cliente automaticamente:
pendente → confirmado: após verificar que o pagamento foi recebido
confirmado → em_preparo: quando a cozinha inicia o preparo
em_preparo → saindo: quando o motoboy sai com o pedido
saindo → entregue: quando o motoboy confirma a entrega

5. Requisitos PWA
O sistema deve funcionar como Progressive Web App em ambos os domínios. O cliente pode instalar o cardápio na tela inicial do celular. A equipe pode instalar o painel admin no tablet ou celular.
Feature
Descrição
Endpoint(s)
manifest.json
Configurar: name, short_name, icons (192×192 e 512×512), display: standalone, theme_color: #1A1A2E, start_url, background_color.
—
Service Worker
Usar next-pwa para geração automática. Cache: stale-while-revalidate para assets, network-first para chamadas de API.
—
Ícones
Gerar ícones do restaurante em múltiplos tamanhos: 72, 96, 128, 144, 152, 192, 384 e 512px.
—
Banner de instalação
Banner nativo do navegador no Android. No iOS: instrução manual exibida em modal (Compartilhar → Adicionar à tela de início).
—
Offline — cardápio
Cache do último cardápio. Banner amarelo informando modo offline. Botão de finalizar pedido desabilitado.
—
Offline — admin
Telas de leitura funcionam com cache. Ações de escrita exibem aviso de conexão necessária.
—
Splash screen
Tela de carregamento com logo do restaurante enquanto o PWA inicializa.
—
Notificações push
Fase 2 — substituiria o WhatsApp como canal de notificações para clientes que instalaram o PWA.
