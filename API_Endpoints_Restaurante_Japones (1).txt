Sistema de Gestão — Restaurante Japonês
Referência completa de endpoints para integração com o frontend
Versão 1.0  |  Junho de 2026
1. Visão Geral
Esta documentação descreve todos os endpoints REST disponíveis na API do sistema. A base URL em desenvolvimento é http://localhost:3000. Em produção, será api.restaurante.com.br.
Convenções utilizadas neste documento:
Público — sem autenticação necessária. Acessível por qualquer cliente.
Clerk (qualquer role) — requer sessão Clerk válida, independente do role.
Admin / Gerente — restrito aos roles admin e gerente.
Admin / Gerente / Garçom — acessível também ao garçom.
Apenas Admin — restrito ao role admin.
Todas as respostas de erro seguem o formato: { &quot;error&quot;: &quot;mensagem descritiva&quot; }

6. Pedidos — Delivery
Fluxo completo de pedidos online. O pedido é criado com status pendente e atualizado conforme o pagamento e preparo avançam.
Ciclo de vida: pendente → confirmado → em_preparo → saindo → entregue → cancelado
Pedidos
Método
Endpoint
Descrição
Auth
GET
/api/pedidos
Lista pedidos. Com ?customer_id=uuid filtra por cliente.
Admin / Gerente
POST
/api/pedidos
Cria pedido. Body: { customer_id, address_id, subtotal, delivery_fee?, notes? }. Valida automaticamente o raio de 20km via Haversine.
Público
GET
/api/pedidos/historico
Histórico paginado com filtros. Params: status, data_inicio (YYYY-MM-DD), data_fim, page, limit. Retorna breakdown com link da NFC-e.
Admin / Gerente
POST
/api/pedidos/validar-localizacao
Valida se lat/lng está dentro do raio de entrega sem criar registro. Body: { latitude, longitude }.
Público
GET
/api/pedidos/:id
Retorna pedido pelo ID.
Admin / Gerente
PATCH
/api/pedidos/:id
Atualiza status ou dados do pedido. Cancelamento exige cancellation_reason. Mudança de status dispara notificação WhatsApp automaticamente.
Admin / Gerente

8. Pagamentos
Integração com Mercado Pago. Suporta Pix (QR Code) e cartão de crédito/débito. O webhook confirma pagamentos de forma assíncrona.
Método
Endpoint
Descrição
Auth
POST
/api/pagamentos
Inicia pagamento. Body: { order_id, method (pix|cartao_credito|cartao_debito), name, phone, token? (cartão), installments?, payment_method? }. Retorna QR Code para Pix ou status imediato para cartão.
Público
POST
/api/webhooks/mercadopago
Recebido automaticamente pelo Mercado Pago após confirmação de pagamento. Valida assinatura HMAC, atualiza status do pedido e dispara workers de NFC-e e WhatsApp.
Mercado Pago (automático)
9. Fechamento de Caixa
Consolidado diário de recebimentos separado por delivery e salão, com breakdown por método de pagamento.
Método
Endpoint
Descrição
Auth
GET
/api/caixa/fechamento
Retorna o fechamento do dia. Param: ?data=YYYY-MM-DD (padrão: hoje). Inclui totais por delivery e salão, breakdown por método (Pix, cartão), total do dia, notas fiscais emitidas e cancelamentos.
Admin / Gerente

10. Configurações do Sistema
Parâmetros operacionais editáveis pelo admin sem necessidade de deploy. Armazenados como chave-valor JSONB.
Método
Endpoint
Descrição
Auth

/api/system_config

Admin
POST
/api/system_config
Cria configuração. Body: { key, value, description? }. Chave deve usar letras minúsculas e underscore.
Apenas Admin
GET
/api/system_config/:key
Retorna configuração pela chave.
Admin
PATCH
/api/system_config/:key
Atualiza valor de uma configuração existente.
Apenas Admin
DELETE
/api/system_config/:key
Remove configuração.
Apenas Admin
Chaves pré-configuradas no sistema:
restaurant_lat / restaurant_lng — coordenadas do restaurante para cálculo do raio de entrega.
delivery_radius_km — raio máximo de entrega em km (padrão: 20).
service_fee_pct — taxa de serviço do salão em % (padrão: 10).
pix_expiration_minutes — minutos até expiração do QR Code Pix (padrão: 30).
restaurant_name / restaurant_cnpj / restaurant_ie — dados fiscais para emissão de NFC-e.
